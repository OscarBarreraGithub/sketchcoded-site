What it is

Sketchcoded is a bulletin board for the app you're about to build. You bring drawings of screens as image files. You pin them to a cork board, drop numbered pins on the parts that do something, and tie yarn from a pin to the screen it leads to. Every pin and every yarn carries plain-language notes: what happens, when, and what data is involved.

Before you draw, you can write down every idea in the plan, assign each to a screen, and let the app turn them into pins once the drawing exists. Screens can hold a web drawing and a mobile drawing of the same view. When the board is ready, you play it like a paper prototype, run the checks, and export a bundle an AI agent can build from.

The example: this website

Open the read-only example: the real Sketchcoded board with the author's hand drawings, pins and yarn. Click Home and walk it. Useful undrawn pages are left to the AI and render from their plan. Isolated planning frames stay in the local backlog, keeping the public example focused. The public copy is refreshed from the local board when the site is published.

Your first local launch opens Your boards, with Little chat available as a separate practice board. Try the six-step tutorial there to practice without changing a board.

Requires Node.js 22.12 or later and npm. These commands work on macOS, Windows and Linux. Open the address printed by the server (normally http://127.0.0.1:5173). Stop it with Ctrl+C when you're done.

Choose a port or storage folder

Use npm run dev -- --port 0 to choose an available port, or supply a number such as 5180. Add --data-dir "./my boards" to choose a storage folder. Without that option, projects stay in .drawcode/ inside the checkout. Run one server per data folder. No account, API key or particular computer username is required.

Move to another computer

Export a project ZIP and import it in the new installation. It carries the drawings, plan, checklist and agent instructions. Local source-folder paths are excluded; reconnect folders on the new computer if you want to refresh their images. The repository README also explains how to transfer the complete data folder.

Set up from the Markdown files

The repository is written to be read by an agent. AGENTS.md holds the working rules, README.md the user guide, and docs/ the original brief, the graph contract, the decisions made along the way and the functionality list. An agent that reads those files knows how to run, test and extend the app without asking.

Everyday controls

Start with Plan. Put ideas in the pool or assign them to planned frames. “Placed” means an idea has become a pin, not that the feature has been implemented. Planned connections appear in Plan and the text outline; the board draws real yarn only.

Import images, add a folder once, or connect a folder to watch it. New and Used sections keep track of your sketches. Drop a sketch on the board or onto a planned frame. Existing snapshots stay intact when source files change.

Drag blank cork to pan, scroll to zoom around the pointer, Shift + scroll to pan, and press F to fit. The zoom slider accepts arrow keys. Browser zoom remains available. Drag a frame to move it or its corner to resize it. A click picks out its connections; its tape title, arrow or a double-click opens the editor.

Frames have P codes, sketches S codes and ideas I codes. “P3 pin 2” names a pin precisely. Codes stay with their items and are not reused after deletion.

Add a pin and describe one intention. Choose Navigation for a route, Content / local action for a heading or behavior that stays here, Link out for an external URL in the description, or Detail reference for a closer illustration. Content and link pins have no yarn. A detail reference never changes app history.

Provisional pins let an agent tie real yarn before a drawing exists. When you add the drawing, place each waiting pin. In the editor, Web / Mobile switches between two drawings of the same screen; each pin can have a position on both.

Threads filters one category: Main path in red, Branch in gold, Detour in blue, Way back in olive, plus two colors you can name. On a crowded board, select a frame to bring its paths and labels forward. Click the cork to release it.

Test flow follows the authored paths. You choose written conditions; they are not evaluated. Back uses app history, Dismiss returns to a dialog's caller, and Start fresh clears app history. Rewind test is a separate testing aid that can undo any test step. Content pins explain their local behavior; external links show their destination.

A frame marked Leave it up to the AI gets a conventional page from its title, purpose, ideas and paths, with working redirects. Forms are a prototype and have no backend. A drawing always takes priority. App outline is the searchable alternative to the board; Plan holds the complete backlog.

Work with your agent

Use Tell the agent in the view you are working on. Paste its three-line prompt into your agent, then add your request underneath. The task brief points to the live board, the relevant instructions and your general checklist. Keep the local app running while the agent reads and writes.

For a new board, choose Just the list, Frames and strings, or Built out. The middle choice makes planned frames and provisional pins with their yarn; Built out also leaves each page to the AI so you can walk it immediately and draw the pages you care about.

The agent checks affected board views and pages left to the AI against the full checklist. When it constructs the site from the board, it checks the finished implementation too. It must inspect the rendered result and report its checks, including overlap and real browser zoom. The graph checker cannot do that job.

Before the final write, the agent asks you to pause editing until the board refreshes. A clean board refreshes automatically; unsaved edits are kept for recovery. Export current work before taking the newer copy if a conflict appears. Reload after the write if the board has not refreshed.

Structural checks

Review flow reads the board as a graph and reports three kinds of finding.

Repair needed

  • Broken references: a yarn to a missing screen, a pin with no screen, a missing image.
  • Yarn attached to a detail reference, a link pin or a content/local-action pin.
  • A Back or Dismiss action with a fixed destination.

Check this path

  • No starting screen, an untitled screen, a pin without a name or intent.
  • A navigation pin with no yarn, a screen nobody can reach, a screen with no way onward.
  • Two branches with the same label, or more than one fallback.
  • A planned frame still waiting for its drawing unless left to the AI; a pin missing from the mobile layout; a link pin without an address.

Use your judgment

  • Branches described in words that may overlap or leave a case out.
  • A one-way path with no structural way back, such as after logging in.
  • A Back action on a screen you can arrive at without history.

You accept an intentional exception with a reason. The reason travels with the export and reopens if the relevant evidence changes. Nothing in words is executed or proved.

Build rules

The full general checklist lives in docs/BUILD_CHECKLIST.md, is served at /api/checklist.md and ships as BUILD-CHECKLIST.md in every export. Each task brief requires the agent to follow verify-the-result. These requirements apply both to board authoring, including pages left to the AI, and to the finished site. The agent reports what passed and what remains unverified.

  • Nothing grows or shrinks because of what was clicked. Dialogs and panels keep a fixed size; their content scrolls.
  • Nothing overlaps. Labels, pins and frames keep clear of each other.
  • Text stays readable and controls reachable at real browser zoom of 125%, 150%, 200% and 250%, at both 1440×900 and 1280×720. Every affected view is checked. Click targets are at least 44px; fields at least 48px.
  • Every scrolling region has a visible scrollbar and a More below hint until the end. Text is at least 12px; long notes stay readable.
  • The page never scrolls; panels do. The board never pans out of sight of its content. Every view works at every zoom.
  • A frame wearing the “Leave it up to the AI” post-it needs no drawing: the builder makes a standard, conventional page from its title, purpose, ideas and yarn. Everything else is built as drawn.

What the AI gets

Export produces a ZIP with:

  • project.json: the canonical graph, layout, library, planning backlog and review decisions.
  • schema.json: the JSON Schema for that file.
  • flow.md: the same specification organized by screen, pin, branch and finding, plus the planning outline. Frames left to the AI are marked there.
  • BUILD-CHECKLIST.md: your general build rules, the ones that hold for every app you make; the agent reads them first.
  • skills/: the agent's instructions, one file each: read a board, build rules, describe pins, connect screens, plan the backlog, resolve findings, walk the flow, talk to Sketchcoded, start a board and verify the result.
  • review.json: current findings and accepted exceptions with reasons.
  • assets/: the drawings.

You rarely need the export while you work. Every view has a Tell the agent button: it copies a three-line prompt naming exactly what you are looking at and the address of a task brief the running app serves for it; the brief carries the task, the skills to read and your rules. Whatever you type under the prompt is part of the task. The agent reads the live board on your computer and writes back through the same local API. A new board is written at the level you choose: just the to-do list, frames with the strings already tied, or built out, where every frame is left to the AI and Test flow walks the whole site: real pages you scroll, buttons that follow your yarn, forms and dialogs, with nothing behind them. You take the post-it off the one or two pages you want to draw yourself.

FAQ

How do I recover unsaved work?

Keep the tab open if saving fails. Restart the local server if needed, then retry. For a conflict, Export current work before taking the newer copy; importing that ZIP creates a separate board. Saved files also have a previous-version .json.bak backup. Stop the server before manually restoring it, and preserve both copies.

Does it need an API key?

No. Nothing calls a model. Tell the agent hands one task at a time to whichever agent you use, and the export is the full handoff.

Where are my files?

In a .drawcode folder next to the app: one JSON file per board and a copy of each image. The folder you connect is read only.

Can I use photos of paper?

Yes, as image files on your computer: PNG, JPEG, WebP, GIF, AVIF, TIFF or SVG. There is no phone capture.

Is there a mobile app?

No. Sketchcoded runs in a desktop browser. You can design mobile layouts for your own app: each screen can hold a web drawing and a mobile drawing.

How does the AI part work?

Use Tell the agent for changes to the live board. Export a ZIP when you want a portable specification for building the app or keeping a backup. Sketchcoded itself does not call a model or build the production app: your outside agent follows the board, its instructions and the checklist.

Is it open source?

The source is on GitHub.
